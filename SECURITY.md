# Security policy

Please report suspected vulnerabilities through [GitHub private vulnerability reporting](https://github.com/marcdp/xvault/security/advisories/new). Do not include secrets, passwords, private keys, or a working exploit in a public issue. If GitHub does not offer that form, open a minimal public issue requesting a private reporting channel without disclosing technical details.

Include the affected version, a clear description of the impact, and safe steps to reproduce the issue. Please allow maintainers reasonable time to investigate and coordinate a fix before public disclosure.

Include the affected xvault version, operating system and Python version, impact,
safe reproduction steps, and any suggested mitigation. Please allow maintainers
to investigate and coordinate a fix before public disclosure; no fixed response
or remediation time is promised.

Security fixes target the latest published release and the current default
branch. Older releases are evaluated case by case and should not be assumed to
receive backports. The project security model and its limits are described in
[docs/internals.md](docs/internals.md#security-model).
